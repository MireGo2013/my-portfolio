# 15. Анимации: появление при загрузке, при скролле и при наведении

## Что сделали

Добавили анимации на главной, в Work и Experience, логотип с инициалами в шапке и ссылки с навыков на официальную документацию. Контент при этом остаётся видимым без JavaScript и при просьбе убрать движение.

## Что и зачем

| Файл | Что делает |
| --- | --- |
| `components/animated-text.tsx` | Текст появляется слово за словом |
| `components/reveal.tsx` | Показывает блок, когда до него доскроллили |
| `components/monogram.tsx` | Логотип с инициалами в шапке и вместо фото |
| `lib/skill-docs.ts` | Ссылки на документацию навыков |
| `app/globals.css` | Сами анимации, выезды и разворот карточки |

Почему именно так, и какие были альтернативы:

- **CSS и `IntersectionObserver` против библиотеки `motion`.** Библиотека умеет больше, но добавляет JavaScript и превращает компоненты в клиентские. Здесь хватает пары ключевых кадров и одного наблюдателя, поэтому нового пакета нет.
- **CSS `animation-timeline: view()` против наблюдателя.** Анимация по скроллу на чистом CSS короче, но работает не во всех браузерах. Наблюдатель работает везде.
- **Анимация при загрузке на чистом CSS.** Главная видна сразу, поэтому ей не нужен JavaScript: анимация начинается ещё до гидратации.

## Как это работает

### Слово за словом без JavaScript

```tsx
// ❌ печатать текст через setInterval: клиентский компонент, пустой HTML
const [shown, setShown] = useState('');
```

Такой текст не увидят ни поисковик, ни посетитель с медленным JavaScript. Делаем по-другому: весь текст есть в HTML, а у каждого слова своя задержка анимации.

```tsx
<span className="enter-word" style={{ '--enter-delay': '468ms' }}>
  frontend-разработчик
</span>
```

```css
.enter-word {
  display: inline-block; /* transform не действует на строчный элемент */
  animation: enter-up 0.6s both;
  animation-delay: var(--enter-delay);
}
```

Важный, преважный момент: `both` в `animation` означает, что до начала анимации слово уже находится в стартовом кадре, то есть невидимо. Без этого все слова мелькнули бы на долю секунды, а потом начали появляться. Взяли и запомнили.

Следующий абзац стартует, когда закончился предыдущий. Задержки считаем без изменения переменной в цикле, иначе React Compiler ругается:

```ts
// ❌ let cursor = 0; items.map(() => (cursor += step));
// ✅ задержка = старт + сумма длительностей предыдущих абзацев
const startDelay = TEXT_START_MS + sum(durations.slice(0, index));
```

### Появление при скролле

**IntersectionObserver** это браузерное API, которое сообщает, когда элемент пересёк видимую область. Простыми словами: браузер сам следит за положением блока и вызывает наш колбэк. Нам не нужно слушать `scroll` и считать координаты на каждый кадр.

```ts
// ❌ сотни вызовов в секунду и пересчёт раскладки
window.addEventListener('scroll', () => element.getBoundingClientRect());
```

```ts
// ✅ один наблюдатель на всю страницу
observer ??= new IntersectionObserver((entries) => {
  for (const entry of entries) {
    if (entry.isIntersecting) {
      entry.target.setAttribute('data-visible', '');
      observer.unobserve(entry.target); // показали один раз и забыли
    }
  }
});
```

Компонент ставит только атрибут, а всё остальное делает CSS:

```css
.reveal-left {
  opacity: 0;
  transform: translateX(-4rem);
}
.reveal[data-visible] {
  opacity: 1;
  transform: none;
}
```

### Почему контент не потеряется

У скрытия до прокрутки есть три ловушки, и каждую закрываем отдельно:

```text
JavaScript не загрузился   → <noscript><style>.reveal { opacity: 1 }</style></noscript>
Просьба убрать движение    → @media (prefers-reduced-motion: reduce) { .reveal { opacity: 1 } }
Старый браузер без API     → компонент сразу ставит data-visible
```

Выезд на `4rem` за край мог бы добавить горизонтальный скролл. Его отсекает `overflow-x: clip` у `body`. В отличие от `hidden`, `clip` не ломает закреплённую шапку.

### Разворот карточки

Карточка разворачивается внешним краем к посетителю: у левой колонки вперёд выходит левый край, у правой правый. С первого раза знак угла перепутали, поэтому разберём, откуда он берётся.

```css
/* ❌ у левой карточки к посетителю вышел правый край */
.card-tilt:hover {
  transform: perspective(900px) rotateY(-10deg);
}
/* ✅ левый край вперёд */
.card-tilt:hover {
  transform: perspective(900px) rotateY(10deg);
}
```

Ось Z в CSS смотрит на посетителя. При повороте вокруг оси Y точка с координатой `x` получает глубину `z = -x · sin(угол)`. Для положительного угла у левого края (`x < 0`) глубина положительная, значит, он выходит вперёд. Правая колонка получает тот же поворот с обратным знаком.

`perspective` даёт глубину, без неё `rotateY` выглядел бы как сжатие. Эффект включён только при `(hover: hover)`, потому что на телефоне наведения нет.

## Ещё раз, что мы сделали

Главная проявляется по словам, а боковые ссылки выезжают снизу, и всё это на чистом CSS. Проекты в Work выезжают по очереди слева и справа, а пункты внутри них поднимаются снизу. Карточки в Experience появляются при скролле и разворачиваются при наведении. Навыки ведут на официальную документацию, а в шапке появился логотип с инициалами. Проверили, что контент виден без JavaScript и при просьбе убрать движение. Кайф.

## Вопросы на собеседовании

**Почему для анимации при скролле лучше IntersectionObserver, чем событие scroll?**
`scroll` срабатывает много раз за кадр, а `getBoundingClientRect` в обработчике вызывает пересчёт раскладки. Наблюдатель работает асинхронно и сообщает только о пересечении.

**Какие свойства анимировать, чтобы не было рывков?**
`transform` и `opacity`. Их браузер обрабатывает на этапе композиции, без пересчёта раскладки и перерисовки.

**Как сделать анимацию доступной?**
Уважать `prefers-reduced-motion`, не прятать контент без запасного варианта, не делать анимацию единственным способом что-то сообщить. Бесконечное движение нужно уметь остановить.
