# 11. Графитовая палитра на CSS-переменных

## Что сделали

Перевели весь сайт на одну графитовую тему с медным акцентом, поменяв значения цветов в одном файле, без правок разметки страниц.

## Что и зачем

| Файл | Что изменилось |
| --- | --- |
| `apps/web/src/app/globals.css` | Новая палитра, токен `--surface`, `color-scheme: dark`, цвет выделения текста |
| `contact-form.tsx`, `project-card.tsx` | Поля и карточки получили фон `bg-surface` |

Почему именно так, и какие были альтернативы:

- **Одна тема против светлой и тёмной.** Сайт задуман как графитовый, поэтому блок `prefers-color-scheme` убрали. Две темы означают две палитры, и обе надо проверять на контраст.
- **Контраст считаем, а не оцениваем на глаз.** Простой текст по WCAG AA требует минимум 4.5:1. У нас самое слабое сочетание текста даёт 6.16:1.
- **Шрифты оставили.** IBM Plex Sans и Mono уже поддерживают кириллицу и латиницу, а это пригодится для двух языков.

## Как это работает

Наивный вариант зашивает цвет прямо в компонент:

```tsx
// ❌ сменить палитру значит пройти по всем компонентам
<button className="bg-[#e0935f] text-[#1c1008]">Связаться</button>
```

Захотел поменять акцент, и погнали искать все вхождения по проекту. Часть обязательно пропустишь.

**Дизайн-токен** (design token) это именованное значение дизайна. Простыми словами: компонент говорит не «этот оранжевый», а «акцентный цвет», а само значение лежит в одном месте. Взяли и запомнили.

```css
:root {
  --accent: #e0935f; /* значение, можно менять в рантайме */
}

@theme inline {
  --color-accent: var(--accent); /* Tailwind выплюнет класс bg-accent */
}
```

```tsx
// ✅ компонент не знает конкретный цвет
<button className="bg-accent text-on-accent">Связаться</button>
```

Tailwind смотрит в `@theme` и генерирует утилиты. Браузер подставляет значение `var(--accent)` при отрисовке. Поэтому на этом шаге разметка страниц не изменилась, кроме двух новых фонов. Кайф.

Важный, преважный момент про `color-scheme: dark`. Цвета страницы задаём мы, а скроллбар, календарь и другие встроенные элементы рисует браузер:

```css
/* ❌ без этого у тёмного сайта может быть светлый скроллбар */
/* ✅ браузер рисует свои элементы в тёмном варианте */
:root {
  color-scheme: dark;
}
```

## Ещё раз, что мы сделали

Заменили значения токенов на графит и медь, убрали вторую тему и добавили токен `--surface` для полей и карточек. Посчитали контраст, проверили страницы на компьютере и телефоне: горизонтального скролла нет, unit-тесты зелёные. Компоненты почти не трогали, потому что они знают только названия токенов.

## Вопросы на собеседовании

**Зачем нужны дизайн-токены, если можно писать цвета сразу?**
Токены дают одно место для изменения и общий словарь дизайна. Смена палитры становится правкой значений, а не поиском по всему коду.

**Что такое `color-scheme`?**
Это CSS-свойство, которое говорит браузеру, в какой схеме рисовать встроенные элементы: скроллбары и поля форм. Цвета нашего контента оно само не задаёт.

**Какой контраст нужен для текста?**
По WCAG AA 4.5:1 для обычного текста и 3:1 для крупного. Считается по относительной яркости двух цветов.
