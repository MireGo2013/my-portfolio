# 14. Новая структура сайта: About, Work, Experience и лента навыков

## Что сделали

Пересобрали сайт по новой схеме: главная с историей и лентой логотипов, разделы Work и Experience, боковые ссылки и контент как в резюме.

## Что и зачем

| Файл | Что делает |
| --- | --- |
| `app/[lang]/page.tsx` | About: приветствие, история, резюме, аватар, лента |
| `app/[lang]/work/` | Коммерческие проекты и фриланс |
| `app/[lang]/experience/` | Открытые проекты с GitHub |
| `components/skill-marquee.tsx` | Бегущая лента на чистом CSS |
| `components/social-links.tsx` | Боковые ссылки и подвал на узких экранах |
| `components/avatar.tsx`, `public/avatar.svg` | Заглушка с заделом под фото |
| `lib/skill-logos.ts` | Какие логотипы показывает лента |
| `scripts/clear-content-cache.mjs` | Очищает кэш контента перед сборкой |
| `next.config.ts` | Перенаправление со старого `/projects` |
| Миграция `about_and_achievements` | История о себе, обязанности и достижения раздельно |

Почему именно так, и какие были альтернативы:

- **Simple Icons против SVG вручную.** Лицензия CC0, набор обновляется, импорт по одному логотипу. Пакет работает только на сервере, поэтому в браузер попадают лишь нужные контуры. LinkedIn, Playwright и Zustand в наборе нет: для них простая буквенная замена.
- **CSS-анимация против JS-библиотеки.** Лента не хранит состояние, поэтому компонент остаётся серверным и не добавляет JavaScript.
- **Логотипы в коде против базы.** Это оформление, а не контент: в базе остались навыки по областям, а лента просто выбирает, что показать.

## Как это работает

### Бегущая лента без JavaScript

Первая идея: двигать список в `requestAnimationFrame`.

```tsx
// ❌ клиентский компонент и перерисовка ради чистого оформления
useEffect(() => {
  const id = requestAnimationFrame(tick);
  return () => cancelAnimationFrame(id);
});
```

CSS справляется сам. Но если сдвигать один список, в конце появится пустота, а потом рывок. Поэтому список дублируем и сдвигаем дорожку ровно на половину её ширины:

```css
@keyframes marquee {
  to {
    transform: translateX(-50%);
  }
}
```

```text
[список][копия]    старт: видно начало списка
        [список][копия]  сдвиг на 50%: видно начало копии, а она такая же
```

В момент перезапуска анимации картинка совпадает, и шва не видно. Кайф.

Важный, преважный момент: копия нужна только для глаз, а скринридер прочитал бы все навыки дважды.

```tsx
<ul aria-hidden={hidden || undefined}>
```

### Как уважать настройки посетителя

У некоторых людей движение на экране вызывает дискомфорт, и система об этом сообщает. **`prefers-reduced-motion`** это медиазапрос с этой настройкой. Простыми словами: браузер сообщает CSS, что посетитель просит убрать анимацию. Взяли и запомнили.

```css
@media (prefers-reduced-motion: reduce) {
  .marquee-track {
    animation: none;
  }
  .marquee-copy {
    display: none;
  }
}
```

Лента превращается в обычную сетку логотипов, а контент никуда не пропадает.

### Как тестировать движущийся элемент

```ts
// ❌ Playwright ждёт, пока элемент перестанет двигаться, и падает по таймауту
await page.locator('.marquee-track').hover();
// ✅ контейнер стоит на месте, а наведение на него тоже ставит ленту на паузу
await page.locator('.marquee').hover();
```

### Ловушка кэша между сборками

Вот что выплюнула вторая сборка после смены API:

```text
TypeError: Cannot read properties of undefined (reading 'map')
Export encountered an error on /[lang]/page: /en
```

API в этот момент отвечал правильно, а чистая сборка проходила. Значит, данные пришли не из API.

```ts
// Упрощённая модель - не исходный код Next.js
const key = hash(functionId, args); // getProfile + 'en'
const saved = readFile('.next/cache/fetch-cache', key);
if (saved) return saved; // старая структура ответа
```

Next.js сохраняет результаты `use cache` на диск и использует их в следующей сборке. Код поменялся, а аргументы и ключ остались теми же. Vercel переносит эту папку между сборками, поэтому на проде мы получили бы то же самое, а правка в `seed-data.ts` не попала бы на сайт при новой сборке.

```json
"build": "node scripts/clear-content-cache.mjs && next build"
```

Заметь разницу: кэш `.next/cache/turbopack` с компиляцией кода остаётся, поэтому сборка не замедляется. Удаляем только данные.

### Почему порядок выкладки важен

Новый сайт ждёт в ответе поле `about`. Vercel начинает сборку сразу после push, а Railway ждёт CI. Если запушить всё разом, сборка сайта обратится к старому API и упадёт.

```text
1. Push коммитов API → CI → Railway применяет миграции и запускает новый API
2. Проверяем, что новый API отвечает
3. Push коммитов сайта → Vercel собирает страницы уже из нового API
```

## Вопросы на собеседовании

**Как сделать бесшовную бегущую строку?**
Продублировать содержимое и анимировать `transform` на `-50%` с линейной скоростью. `transform` не вызывает пересчёт раскладки, а копия скрывается от скринридеров через `aria-hidden`.

**Что такое `prefers-reduced-motion`?**
Медиазапрос с настройкой системы, по которой посетитель просит меньше движения. Анимацию при этом убирают, а контент оставляют доступным.

**Как `use cache` может сломать сборку?**
Результаты сохраняются на диск и переиспользуются по ключу из функции и аргументов. Если поменялась структура ответа внешнего API, ключ остаётся прежним, и код получает старые данные. Решение: очищать кэш данных перед сборкой или менять ключ при смене контракта.
