# 13. Сайт на двух языках: адреса, словари и переключатель

## Что сделали

Разнесли сайт по адресам `/ru` и `/en`, перевели весь интерфейс и резюме и добавили переключатель, который остаётся на той же странице и запоминает выбор.

## Что и зачем

| Файл | Что делает |
| --- | --- |
| `src/app/[lang]/` | Все страницы теперь лежат под сегментом языка |
| `src/proxy.ts` | Адрес без языка перенаправляет на адрес с языком |
| `src/i18n/pick-locale.ts` | Выбирает язык: cookie, затем `Accept-Language`, иначе английский |
| `src/i18n/dictionaries/` | Подписи интерфейса на двух языках |
| `src/i18n/server.ts` | `getDictionary`, `resolveLocale`, `pageMetadata` |
| `src/components/language-switcher.tsx` | Переключатель языка |
| `packages/shared/src/contact.ts` | Коды ошибок вместо готовых русских текстов |
| `public/cv/Sobol_Vladislav_CV_EN.pdf` | Английское резюме без личных данных |

Почему именно так, и какие были альтернативы:

- **Встроенный подход Next.js против `next-intl`.** Библиотека даёт склонения и сложные форматы, а у нас простые строки. В её руководстве нет ни слова про Cache Components, а встроенный подход описан в документации самого Next.js. Нового пакета не понадобилось.
- **Язык в адресе против cookie.** С одним адресом поисковик видит только одну версию, а ссылкой на английскую страницу не поделиться.
- **Коды ошибок против двух схем.** Схема остаётся одна на клиенте и сервере и не знает про языки. Текст подставляет тот, кто ошибку показывает.
- **Свой разбор `Accept-Language` против `negotiator`.** Для двух языков хватает 15 строк с тестами.

## Как это работает

### Откуда страница знает язык

Первый порыв: хранить язык в состоянии.

```tsx
// ❌ сервер не знает про useState, HTML соберётся на одном языке
const [locale, setLocale] = useState('ru');
```

Страницы собираются заранее, ещё до первого посетителя. Браузерного состояния в этот момент не существует. Next.js говорит: дай мне список значений параметра, и я соберу страницу для каждого.

```tsx
// app/[lang]/layout.tsx
export function generateStaticParams() {
  return LOCALES.map((lang) => ({ lang })); // ru и en
}
```

**Динамический сегмент** (dynamic segment) это часть адреса, значение которой приходит в страницу параметром. Простыми словами: папка `[lang]` превращает одну страницу в `/ru/skills` и `/en/skills`, и на сборке получаются два готовых HTML-файла. Взяли и запомнили.

Функции контента получают язык аргументом:

```ts
export async function getSkills(locale: Locale) {
  'use cache'; // аргументы входят в ключ кэша
  return contentApi().getSkills(locale);
}
```

```ts
// Упрощённая модель - не исходный код Next.js
const key = JSON.stringify(['getSkills', locale]);
if (cache.has(key)) return cache.get(key);
```

Поэтому русская и английская версии не перепутаются в кэше.

### Что происходит, когда заходят на `/`

Страницы `/` больше нет, зато есть **proxy** (раньше назывался middleware). Простыми словами: функция, которая выполняется до страницы и может заменить ответ.

```ts
export function proxy(request: NextRequest) {
  const firstSegment = request.nextUrl.pathname.split('/')[1] ?? '';
  if (hasLocale(firstSegment)) return NextResponse.next();

  const locale = pickLocale(cookie, acceptLanguage);
  return NextResponse.redirect(url); // / -> /ru, /skills -> /en/skills
}
```

Важный, преважный момент: PDF и иконка не должны попасть под перенаправление, иначе `/cv/...pdf` превратится в `/ru/cv/...pdf` и выплюнет 404. Их отсекает `matcher`:

```ts
matcher: ['/((?!_next|.*\\..*).*)'];
```

### Как разобрать `Accept-Language`

Браузер присылает список с приоритетами:

```text
Accept-Language: de-DE,de;q=0.9,ru;q=0.5
```

```ts
// ❌ смотрит только на первый язык: этот посетитель получит английский
const language = header.split(',')[0];
```

Здесь первый язык немецкий, которого у нас нет, а русский посетитель всё-таки понимает. Сортируем по `q`, отбрасываем `q=0` и берём первый поддерживаемый. Значение cookie проверяем тем же `hasLocale`: присланное клиентом верить на слово нельзя.

### Как перевести ошибки, не раздвоив схему

Раньше схема хранила готовый текст, и сервер отвечал по-русски даже англоязычному сайту.

```ts
z.string().min(2, 'Укажите имя: минимум 2 символа'); // ❌
z.string().min(2, 'nameTooShort'); // ✅ код, а не текст
```

```tsx
// Форма получает словарь нужного языка и подставляет текст
const errorText = (error) =>
  isContactErrorCode(error?.message)
    ? dictionary.errors[error.message]
    : undefined;
```

Клиентский компонент получает только свой кусок словаря пропсом, поэтому чужие подписи не попадают в браузер. Кайф.

### Почему словарь один источник правды для типа

```ts
export type Dictionary = typeof ru;
export const en: Dictionary = {
  /* ... */
}; // забыл строку, и сборка упала
```

Если забыть перевод, ошибку покажет компилятор, а не посетитель. Этот же приём мы заюзали для контента в `Record<Locale, T>`.

### Как достать язык на странице 404

`not-found` не получает `params`, и это ловушка. Спасает `next/root-params`:

```ts
import { lang } from 'next/root-params';
const value = await lang();
```

Ещё один нюанс: `not-found` сработает только при вызове `notFound()`, а неизвестный адрес под `[lang]` просто не находит маршрут. Поэтому есть `[...rest]/page.tsx`, который ловит всё остальное и вызывает `notFound()`.

## Ещё раз, что мы сделали

Перенесли страницы под `[lang]` и собрали их заранее для обоих языков. Proxy отправляет посетителя с `/` на нужный язык: сначала смотрит на его выбор в cookie, потом на настройки браузера. Подписи вынесли в словари, а компилятор следит за полнотой перевода. Схема формы теперь отдаёт коды ошибок. Резюме открывается и скачивается на текущем языке. Проверили на продакшен-сборке и в Docker, погнали дальше.

## Вопросы на собеседовании

**Как устроена мультиязычность в Next.js App Router?**
Сегмент `[lang]` в адресе, `generateStaticParams` для заранее собранных страниц, словари на сервере и proxy для перенаправления с адреса без языка. Клиенту передаём только нужные строки.

**Почему язык лучше хранить в адресе?**
Каждая версия получает свой адрес. Её можно проиндексировать, закэшировать на CDN и отправить ссылкой. С cookie один адрес отдавал бы разный контент, и кэш пришлось бы делить по этому cookie.

**Что такое `hreflang` и зачем он?**
Это указание поисковику, что у страницы есть версии на других языках. Он может показать посетителю подходящую и не считать версии дублями. Next.js выводит такие ссылки из `alternates.languages`.
