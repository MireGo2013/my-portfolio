# 05. Разделы сайта и навигация

## Что сделали

Добавили страницы опыта, проектов и стека на реальных данных из API, общую шапку с навигацией и русскую страницу 404.

## Что и зачем

| Файл | Зачем нужен |
| --- | --- |
| `src/app/experience`, `projects`, `skills` | По статической странице на раздел |
| `src/app/layout.tsx` | Общая шапка, контейнер и шаблон заголовков |
| `src/app/not-found.tsx` | Своя страница 404 |
| `src/components/nav-link.tsx` | Единственный клиентский компонент: подсветка текущего раздела |
| `src/components/experience-item.tsx`, `project-card.tsx`, `stack-list.tsx` | Карточки контента |
| `src/lib/content.ts` | Функции `getExperience`, `getProjects`, `getSkills` со своими тегами кэша |
| `src/lib/format-period.ts` | Даты вида `12.2021 — 07.2026` |

Почему именно так, и какие были альтернативы:

- **Отдельные страницы против одной с якорями.** В плане проекта разделы описаны как страницы, и маршруты лучше показывают SSG, а у каждого раздела свой заголовок для поиска. Цена: лишний клик по сравнению с одной длинной страницей.
- **Контакты в меню пока нет.** Страница появится вместе с формой на следующем шаге, а ссылка в никуда хуже её отсутствия.
- **Новых пакетов нет.** Всё закрыл уже установленный стек.

## Как это работает

### Почему только один клиентский компонент

```tsx
// ❌ так не работает: шапка серверная, а хук работает только в браузере
export function SiteHeader() {
  const pathname = usePathname(); // Next.js: стоп, тут нужен 'use client'
}
```

Можно сделать `'use client'` на всю шапку, но тогда в браузер уедет больше кода, чем нужно.

**Серверный компонент** (Server Component) выполняется на сервере или на сборке, а в браузер попадает только результат. **Клиентский компонент** (Client Component) отмечен `'use client'`. Простыми словами: его HTML тоже рендерится заранее, но JS-код компонента дополнительно уезжает в браузер, и там React его «оживляет» (hydration).

```tsx
// ✅ граница 'use client' проведена как можно ниже
'use client';

export function NavLink({ href, label }: { href: string; label: string }) {
  const isActive = usePathname() === href;
  return <Link href={href} aria-current={isActive ? 'page' : undefined}>{label}</Link>;
}
```

Взяли и запомнили: **`'use client'` ставим на самый маленький компонент, которому реально нужен браузер**. Карточки опыта и проектов остались серверными.

Активный пункт отмечаем не классом, а атрибутом `aria-current="page"`. Его читают скринридеры, а стили цепляются к нему же через `aria-[current=page]:`. Одна правда на двоих, кайф.

### Почему дату форматируем без Date

```ts
// ❌ так не работает: результат зависит от часового пояса
new Date('2021-12').toLocaleDateString('ru-RU', { month: '2-digit', year: 'numeric' });
```

Строка `'2021-12'` разбирается как полночь первого декабря по **UTC**. А `toLocaleDateString` показывает её в поясе той машины, где выполняется. В поясе западнее Гринвича это ещё 30 ноября, и на сайте появится `11.2021`.

Важный, преважный момент: дата здесь это просто подпись, вычислять с ней нечего. Поэтому никакого `Date`, а обычная работа со строкой:

```ts
// ✅
function formatMonth(month: string): string {
  const [year, monthNumber] = month.split('-');
  return `${monthNumber}.${year}`;
}
```

### Запрашиваем профиль и в layout, и на странице

И шапке, и первому экрану нужен профиль. Вытаскивать его в одном месте и прокидывать вниз пропсами в App Router незачем, ведь layout и страница это отдельные деревья.

```tsx
const profile = await getProfile(); // в layout.tsx
const profile = await getProfile(); // в page.tsx
```

Лишнего запроса к API не будет, потому что `getProfile` помечена `use cache`:

```ts
// Упрощённая модель - не исходный код Next.js
async function getProfile() {
  const key = 'getProfile:[]';
  if (cache.has(key)) return cache.get(key); // второй вызов берёт готовое
  const value = await contentApi().getProfile();
  cache.set(key, value);
  return value;
}
```

### Шаблон заголовков

```ts
// layout.tsx
title: {
  default: `${profile.fullName}, ${profile.title}`, // для главной
  template: `%s | ${profile.fullName}`,             // для остальных
},

// experience/page.tsx
export const metadata = { title: 'Опыт' };
// Итог: Опыт | Владислав Соболь
```

Страница задаёт только свою часть, а имя подставляет layout.

### Как тестировали клиент на все эндпоинты

Четыре метода клиента устроены одинаково, поэтому поведение проверяется одной таблицей через `describe.each`: данные, ошибка 500, недоступный API.

Внутри клиента есть небольшая тонкость:

```ts
// ❌ опасно проверять так: данные могут быть любыми, а не только объектом
if (!data) throw new Error(/* ... */);

// ✅ ошибка это только отсутствие данных. Пустой список это нормальный ответ
if (data === undefined) throw new Error(/* ... */);
```

Отдельный тест закрепляет, что пустой `[]` ошибкой не считается.

В тесте `NavLink` заменили `next/navigation` через `vi.mock`: вне Next.js роутера нет, а нам важно проверить только сравнение адресов.

## Вопросы на собеседовании

**Чем серверный компонент отличается от клиентского?**
Серверный выполняется на сервере или на сборке, его код не попадает в браузер, и он может сразу получать данные. Клиентский дополнительно загружается в браузер и получает доступ к состоянию, эффектам и браузерным API. HTML заранее рендерятся оба.

**Зачем `rel="noopener noreferrer"` у внешних ссылок?**
`noopener` не даёт открытой вкладке получить доступ к нашей через `window.opener`. `noreferrer` не передаёт ей адрес, с которого перешли. Современные браузеры включают `noopener` для `target="_blank"` по умолчанию, но явное указание ничего не стоит.

**Почему вызов `getProfile` дважды не приводит к двум запросам?**
Функция помечена `use cache`, и второй вызов получает результат из кэша по тому же ключу. На сборке оба результата попадают в статический HTML, поэтому при открытии страницы запросов к API нет вообще.
